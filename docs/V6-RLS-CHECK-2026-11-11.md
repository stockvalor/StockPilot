# V6 — Contrôle RLS du 11 novembre 2026

## Résultats constatés sur le projet Supabase StockPilot AI
- Les tables `companies`, `products`, `stockpilot_backups` ont des politiques SELECT fondées sur `auth.uid()` et l'appartenance à l'entreprise.
- `products` possède SELECT/INSERT/UPDATE/DELETE avec vérification de l'entreprise propriétaire. UPDATE possède USING et WITH CHECK.
- `companies` possède SELECT/INSERT/UPDATE/DELETE réservés au propriétaire. UPDATE possède USING et WITH CHECK.
- `stockpilot_backups` possède SELECT/INSERT réservés au propriétaire, sans politique UPDATE/DELETE.
- Test transactionnel non persistant : simulation du rôle `authenticated` avec un identifiant utilisateur étranger `00000000-0000-4000-8000-000000000001`. Résultat : 0 entreprise, 0 produit, 0 sauvegarde visible.

## Limites
- Les produits de la base étaient vides lors du précédent inventaire ; le test à 0 produit ne démontre pas à lui seul un cloisonnement sur des produits réels.
- Aucun test de deux sessions Auth réelles dans Chrome n'a été effectué.
- Les stocks et commandes locaux restent partagés dans le navigateur : **la V6 n'est pas encore multi-entreprise sûre pour des données réelles**.
- Aucune donnée de production n'a été créée, modifiée ou supprimée par ce contrôle.
