# Recette de la candidate V6

Code et tests vérifiés à `76c47b3ded8aade8143ac31d39afb5d05f526e12`, issu de la candidate `f0abe238edabcee57d2cd0428cf2cc12568b6d52`. GitHub Pages est configuré pour se déployer sur les mises à jour de `main` ou manuellement. Cette recette a été enregistrée sur la branche d’audit.

- Référence V5. Le point de sauvegarde `backup-2026-11-12-avant-securisation` pointe sur `ce73c4c9bcecfe2eddb0ea25f6db462a66a3fc28`. C’est une référence Git retrouvée, sans preuve qu’elle soit la version V5 validée. Aucun fichier de version existante hors `candidate/v6/` n’a été modifié.
- Corrections reprises. La candidate utilise déjà la séparation démo/compte, le filtrage par entreprise et les RPC v2. Les branches de correction historiques divergent et ont servi à vérifier les critères, sans intégrer leurs préversions.
- Supabase. Lecture des métadonnées uniquement. Neuf tables publiques, 18 politiques. Six fonctions SECURITY DEFINER publiques, dont cinq autorisées à `authenticated` et aucune à `anon`. Les cinq exigent une session et vérifient la propriété de l’entreprise. La sixième, `stockpilot_receive_order`, n’est exécutable par aucun de ces deux rôles. Les deux RPC historiques restent à couvrir via Auth et Data API sur une instance isolée. Le modèle PGlite ne comprend pas tous les déclencheurs, les RPC historiques ni Auth.
- Sauvegardes. Vérification par les RPC existantes, qui utilisent la représentation PostgreSQL ayant servi à calculer l’empreinte. Chromium avec API simulée vérifie l’acceptation d’une copie valide, le refus d’une empreinte invalide et le téléchargement JSON. Aucune restauration exécutée.
- Instance de recette. Le projet accessible contient uniquement la branche de production. La création d’une branche de recette a été refusée par Supabase (fonction réservée au forfait Pro).
